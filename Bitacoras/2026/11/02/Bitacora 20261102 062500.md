## ANÁLISIS (gstack + SDD)

### Contexto del Sistema
Synergia Móvil no nació en el vacío; surgió tras 7 años de experiencia de campo en transporte y la auditoría exhaustiva de tres implementaciones preexistentes que operaban en el ecosistema de Fundetaxcol:
1. **`fundetaxcol_flutter`** (`C:\Workspaces\fundetaxcol_flutter`): Aplicación móvil de referencia directa en Flutter 2.x (Dart), orientada exclusivamente a Android (`applicationId: co.synergiapos.fundetaxcol`), con 14 vistas operativas, consumo de Odoo JSON-RPC e impresión térmica Bluetooth.
2. **`addons_fundetaxcol`** (`C:\Workspaces\addons_fundetaxcol` / `/opt/synergia/odoo-11.0`): Backend transaccional ERP en Odoo 11 con 17 modelos de negocio para control de bahías, turnos, pagos, conceptos y parque automotor.
3. **`fundetaxcol`** (`C:\Workspaces\fundetaxcol`): Aplicación previa en Python (FastAPI + Flet) con persistencia en Google Firebase Firestore (`fundetaxcolapp`), evaluada y descartada como base móvil por carecer de empaquetado APK nativo.
4. **Servicios de soporte periféricos**:
   - `server_rt_odoo` (`/opt/server_rt_odoo`): Microservicio Node.js en puerto 3000 para WebSockets en tiempo real.
   - `C:\proxyServer`: Proxy de impresión local en Windows para térmicas ESC/POS de 80mm vía Spooler Win32 (`/hw_proxy/print_raw`).

### Problema (Iron Law)
Identificar y certificar con rigor militar las fuentes primarias y compromisos de arquitectura sobre los que se sustenta `synergia_movil`:
- Evitar ambigüedades respecto al origen de los modelos de datos, flujos de interfaz y protocolos de comunicación.
- Documentar por qué se adoptó una arquitectura multiplataforma unificada en Flutter 3 (Android + Windows Desktop) en lugar de mantener las bases heredadas aisladas.
- Mantener intacto el **Perímetro Hermético (Regla 4)** garantizando que el alcance permanezca estrictamente acotado a `synergia_movil` y la infraestructura de `fundetaxcol.co`.

### Decisiones de Diseño (SDD)

| Componente | Proyecto Base (`fundetaxcol_flutter`) | Proyecto Python (`fundetaxcol`) | Decisión Canónica para Synergia Móvil |
|---|---|---|---|
| **Tecnología UI** | Flutter 2.x (Dart 2.12 obsoleto) | FastAPI + Flet (Python) | **Flutter 3.44.0 (Dart 3.x)** con Null Safety nativo y reactividad GetX. |
| **Plataformas Soportadas** | Únicamente Android Móvil | Desktop Local / Web | **Multiplataforma Nativa**: Android (Smartphones/Tablets) + Windows x64 (.exe). |
| **Manejo de Temas** | Fijo Claro (`ThemeApp.light`) | Flet Default | **Tema Dual Dinámico**: Modo Oscuro (noche/cabina) y Modo Claro (sol/exteriores). |
| **Topología Backend** | Odoo 11 HTTP/80 directo | Firebase Firestore / Localhost | **Odoo JSON-RPC Parametrizable**: Conexión al servidor `fundetaxcol.co` con reverse proxy Caddy (HTTP/HTTPS dual). |
| **Capa de Impresión** | Solo Bluetooth Android (`blue_thermal_printer`) | N/A | **Impresión Híbrida**: Bluetooth nativo (móvil) + RAW Socket/Win32 Spooler (Windows). |
| **Gobernanza** | Desarrollo empírico no estructurado | Scripts sueltos | **OpenSpec + gstack + SDD**: Especificaciones formales y trazabilidad estricta. |
