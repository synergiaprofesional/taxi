## 🔬 2. Diagnóstico de Causa Raíz y Trazado de Datos

### Desfase Horario de Odoo UTC a Hora Colombia
- **Causa Raíz:** Odoo almacena datetimes en PostgreSQL en formato ISO-8601 UTC sin sufijo `Z` (`YYYY-MM-DD HH:MM:SS`). Dart interpretaba el string como hora local de la máquina en vez de UTC.
- **Solución Canónica:** Se implementaron las funciones `parseOdooDateTime(raw)` y `parseDate(val)` en `payment_model.dart` y `turno_model.dart`:
  ```dart
  DateTime parseOdooDateTime(dynamic raw) {
    if (raw == null || raw == false) return DateTime.now();
    var str = raw.toString().trim();
    if (str.isEmpty) return DateTime.now();
    if (!str.endsWith('Z') && !str.contains('+') && !str.contains('-')) {
      str = '${str.replaceAll(' ', 'T')}Z';
    }
    final dt = DateTime.tryParse(str);
    return dt != null ? dt.toLocal() : DateTime.now();
  }
  ```

### Rediseño de Tarjetas: Eliminación de Columna Trailing y Adopción de 3 Filas
- **Problema Anterior:** Las tarjetas utilizaban un `Row` con un `Expanded(Column)` para datos de texto y un `Column(trailing)` a la derecha para la hora y el valor. Esto comprimía excesivamente la información horizontal y obligaba a concatenar el conductor y el destino en una sola línea, sin espacio para la dirección.
- **Solución:** Se eliminó la columna trailing derecha. La hora y el valor monetario se subieron a la Fila 1 usando un `Spacer()` que ancla el importe al extremo derecho. Se liberó la Fila 2 para el conductor y se creó la Fila 3 para la bahía (en pagos) y para el destino con dirección/nota (en despachos).
