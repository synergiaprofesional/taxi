## Objetivo
Análisis técnico comparativo de empaquetado móvil (.apk) y topología de red/conexión a datos entre los proyectos de referencia `fundetaxcol_flutter` y `fundetaxcol`, estableciendo las bases para la arquitectura de red y el empaquetado de **Synergia Móvil**.

## ANÁLISIS (gstack + SDD)

### Contexto del Sistema
El ecosistema heredado de Fundetaxcol se compone de tres implementaciones:
1. `addons_fundetaxcol`: ERP Odoo (Python) con 17 modelos de negocio para bahías, turnos, pagos y recaudos.
2. `fundetaxcol`: Aplicación en Python (FastAPI + Flet) con persistencia en Google Firebase Firestore.
3. `fundetaxcol_flutter`: Aplicación móvil desarrollada en Flutter (Dart) con integración directa a Odoo mediante protocolo JSON-RPC (`odoo_rpc`) y WebSockets.

Para **Synergia Móvil**, se requiere una base de código moderna, unificada para Android y Windows Desktop, conociendo con exactitud cuál de los dos repositorios previos implementa la generación nativa de instaladores Android (.apk) y cuál es el esquema de comunicación con el backend (IP vs Dominio).

### Problema (Iron Law)
Determinar con precisión quirúrgica, inspeccionando archivos de configuración de compilación nativa y código fuente:
1. ¿Cuál proyecto fue configurado y estructurado para generar paquetes `.apk` para dispositivos Android?
2. ¿Cómo se comunican con los servidores de datos: usan dirección IP o nombre de dominio? ¿Dónde se parametriza y qué protocolos emplean?

  * Archivo `android/app/src/main/AndroidManifest.xml`:
    * Permisos móviles: `INTERNET`, `BLUETOOTH`, `BLUETOOTH_ADMIN`, `ACCESS_COARSE_LOCATION`, `VIBRATE`.
    * Diseñado para terminal móvil con impresión térmica portátil Bluetooth ESC/POS.
* **`C:\Workspaces\fundetaxcol`**:
  * No cuenta con configuración Android, Gradle ni manifiesto. Es una aplicación pura Python (FastAPI + Flet) orientada a ejecución local con `uvicorn` y `python main.py`.

#### 2. Topología de Conexión a Datos (Dominio vs IP)
* **`fundetaxcol_flutter` (Móvil / Odoo JSON-RPC)**:
  * Archivo `lib/controllers/global/preferences.controller.dart`:
    ```dart
    const _host = "fundetaxcol.co";
    const _port = 80;
    const _portSocket = 3000;
    const _db = "fundetaxcol";
    ```
  * **Conclusión:** Utiliza **DOMINIO** (`fundetaxcol.co`). No hay direcciones IP hardcodeadas.
  * **Protocolo de datos:** Odoo JSON-RPC a través de `http://fundetaxcol.co:80` (base de datos `fundetaxcol`).
  * **Protocolo de tiempo real:** WebSockets en `http://fundetaxcol.co:3000`.
  * **Persistencia local:** Utiliza `LocalStorage` para permitir sobreescribir el host dinámicamente desde la vista de configuración.
* **`fundetaxcol` (FastAPI + Flet + Firebase)**:
  * Frontend: `BASE_URL = "http://localhost:8000/api/v1"` (IP / loopback local).
  * Backend: Conexión cloud a **Firebase Firestore** con proyecto `fundetaxcolapp` y credenciales de cuenta de servicio.

### Decisiones de Diseño (SDD)

| Criterio | `fundetaxcol_flutter` | `fundetaxcol` | Decisión para Synergia Móvil |
|---|---|---|---|
| **Tecnología Frontend** | Flutter (Dart) | Flet (Python) | **Flutter 3 Multiplataforma**: Soporte nativo Android y Windows Desktop (.exe). |
| **Generación APK** | Sí (`applicationId: co.synergiapos.fundetaxcol`) | No | Reutilizar y modernizar la estructura Gradle de Flutter a `com.synergia.movil`. |
| **Estrategia de Red** | Dominio configurable (`fundetaxcol.co`) | Localhost (`localhost:8000`) | **Dominio parametrizable con fallback**: Configurable vía variables de entorno y `LocalStorage`. |
| **Impresión Térmica** | Bluetooth nativo ESC/POS | N/A | **Capa dual**: Bluetooth para móvil + USB/Spooler Windows para escritorio. |
