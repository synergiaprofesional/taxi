# Bitácora Synergia Móvil — Sesión 2026-10-17 175430

## Objetivo
Documentar la decisión técnica de adoptar **Caddy Server** como reverse proxy en el servidor `fundetaxcol.co`, detallando la inspección del servicio systemd de Odoo 11, la resolución de conflictos de puertos y la estrategia de soporte dual (HTTP para terminales legacy + HTTPS para Synergia Móvil).

---

## ANÁLISIS (gstack + SDD)

### Contexto del Sistema
El servidor en producción aloja una instancia de Odoo 11.0 gestionada por Systemd bajo el servicio `odoo_80.service` (`/opt/synergia/odoo-11.0/odoo-bin -c /opt/synergia/odoo-11.0/odoo_80.conf`). Actualmente está enlazada directamente al puerto 80 sin capa de terminación TLS ni proxy inverso.

### Problema (Iron Law)
1. Si se instala un certificado SSL y se redirige HTTP a HTTPS de forma estándar, las terminales móviles heredadas (`fundetaxcol_flutter`) se rompen debido al vicio de concatenación de protocolo en su código fuente Dart (`http://https://...` o pérdida de payload en redirecciones POST 301).
2. Odoo está ocupando el puerto `0.0.0.0:80`, lo que impide que un servidor web / reverse proxy tome el puerto 80 para orquestar tráfico.
3. Se requiere una solución moderna, liviana y automatizada que no dependa de cron jobs manuales de renovación de certificados.

### Decisiones de Diseño (SDD)

| Criterio | Caddy v2 (Elegido) | Nginx | Apache |
|---|---|---|---|
| **Gestión SSL/TLS** | **Automática y nativa** con Let's Encrypt / ZeroSSL. | Manual vía Certbot y crontabs. | Manual vía Certbot y módulos. |
| **Soporte WebSockets** | Nativo y transparente. | Requiere headers explícitos. | Requiere proxy_wstunnel. |
| **Soporte Dual (HTTP + HTTPS)** | Bloques limpios `fundetaxcol.co` y `http://fundetaxcol.co`. | Bloques redundantes `server {}`. | VirtualHosts extensos. |
| **Configuración** | Declarativa y concisa (~10 líneas). | Extensa y propensa a desajustes. | Verbosa. |

## EJECUCIÓN

### 1. Auditoría en Vivo del Servicio Systemd
Se ejecutó el script permanente [`scripts/check_odoo_service.py`](file:///c:/Workspaces/synergia_movil/scripts/check_odoo_service.py) confirmando:
* Definición: `/etc/systemd/system/odoo_80.service`
* Binario: `/opt/synergia/odoo-11.0/odoo-bin`
* Configuración: `/opt/synergia/odoo-11.0/odoo_80.conf`
* Caddy: No instalado en el sistema operativo.

### 2. Plan de Despliegue de Caddy
1. Modificar `/opt/synergia/odoo-11.0/odoo_80.conf` para cambiar el puerto de Odoo a `xmlrpc_port = 8069` e interfaz `127.0.0.1`.
2. Reiniciar `odoo_80.service`.
3. Instalar Caddy v2 oficial vía repositorio APT.
4. Desplegar el `Caddyfile` con soporte dual:
   - HTTPS nativo para el dominio `fundetaxcol.co`.
   - HTTP explícito sin redirección para no romper terminales legacy.
