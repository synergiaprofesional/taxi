## 🔍 Análisis y Diagnóstico de Causa Raíz (gstack)

### 1. Duplicidad de la palabra "TURNO: TURNO # 12"
- **Pila Trazada:** Base de Datos Odoo 11 $\rightarrow$ `TicketDataModel.turnoNumero` $\rightarrow$ `PrinterService._extraerTurnoEnUnaLinea` $\rightarrow$ ESC/POS / HTML.
- **Causa Raíz:** En Odoo 11, el campo `name` de la tabla `fundetaxcol_turno` ya contiene la palabra `"Turno # 12"` o `"TURNO 12"`. Al renderizar el ticket, la plantilla concatenaba `'TURNO: $turnoLinea'`, produciendo visualmente: `TURNO: TURNO # 12`.
- **Solución:** Se implementó una expresión regular de limpieza que remueve cualquier prefijo existente (`^TURNO\s*:?\s*#?\s*`) para que el ticket siempre imprima de forma limpia: `TURNO: 12`.

### 2. Error C1083 en Compilación de Windows (`cpp_client_wrapper`)
- **Pila Trazada:** `flutter build windows --release` $\rightarrow$ MSBuild $\rightarrow$ `flutter_wrapper_app.vcxproj`.
- **Causa Raíz:** El directorio `windows/flutter/ephemeral/cpp_client_wrapper` no contenía los archivos fuente `.cc` requeridos por MSBuild (`core_implementations.cc`, `standard_codec.cc`, etc.).
- **Solución (FIX-006):** Se sincronizaron los archivos fuente C++ directamente desde el SDK de Flutter (`C:\flutter\bin\cache\artifacts\engine\windows-x64\cpp_client_wrapper`).

### 3. Error de Sintaxis de Subshell en `deploy_phone.bat`
- **Pila Trazada:** `deploy_phone.bat` $\rightarrow$ `cmd.exe` $\rightarrow$ `for /f ('adb devices | findstr...')`.
- **Causa Raíz:** `cmd.exe` falla con `1\ was unexpected at this time` al evaluar comillas dobles y pipes simultáneos dentro de un bucle de lote.
- **Solución (FIX-008):** Se desacopló la detección del serial del teléfono hacia un script auxiliar PowerShell limpio [`detect_phone.ps1`](file:///c:/Workspaces/synergia_movil/detect_phone.ps1) y se copiaron todos los scripts `.bat` y `.ps1` a la raíz del repositorio.

### 4. Configuración Caddyfile en `:80`
- **Pila Trazada:** Tablet/Móvil Wi-Fi (`192.168.6.227`) $\rightarrow$ Caddy Reverse Proxy $\rightarrow$ Waitress/Python en `127.0.0.1:4000`.
- **Causa Raíz:** Especificar `192.168.6.227` sin puerto en Caddy activa certificados TLS autofirmados que Android rechaza.
- **Solución:** Configuración limpia con `:80`:
  ```caddyfile
  :80 {
      reverse_proxy 127.0.0.1:4000
  }
  ```
  Recargado dinámicamente mediante la API administrativa `http://localhost:2019/load`.
