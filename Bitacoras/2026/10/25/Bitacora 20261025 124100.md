# Bitácora Synergia Móvil — Sesión 2026-10-25 124100

## Objetivo
Diagnosticar exhaustivamente bajo la Iron Law de gstack por qué los despachos efectuados y los turnos enturnados hoy (25 de octubre de 2026) se visualizaban en tiempo real en los tableros web oficiales de Odoo 11 (`fundetaxcol.co/tablero_turnos`), pero se mostraban completamente vacíos en la Tablet Lenovo y el Teléfono Xiaomi. Corregir el desacoplamiento de IDs de bahía en la arquitectura del cliente Flutter, verificar compilación en 0 issues y desplegar físicamente a todos los entornos (Tablet, Móvil y Windows Desktop) conforme a FIX-001 y FIX-002 de `ERRORES.md`.

---

## ANÁLISIS (gstack + SDD)

### Contexto del Sistema
En la infraestructura de Fundetaxcol, el módulo backend `fundetaxcol_movil` en Odoo 11 maneja la operativa de turnos y despachos de vehículos para las terminales y bahías:
- `fundetaxcol.bahia`: Entidad maestra de bahía física estática (ej: ID `4` = Garita, ID `2` = 29D, ID `1` = Av. Lago).
- `fundetaxcol.sesion.bahia`: Entidad operativa de sesión diaria de la bahía (ej: ID `8843` = Garita para el 2026-10-25, ID `8842` = 29D para el 2026-10-25).
- `fundetaxcol.turno`: Cada turno generado está vinculado por Many2one `bahia_id` hacia `fundetaxcol.sesion.bahia`.
- Frontend Flutter (`synergia_movil`): La aplicación móvil y tablet selecciona la sesión activa desde `fundetaxcol.sesion.bahia` (cuyo ID numérico es `8843` o `8842`), almacenándolo en `TurnoController.bahiaIdActual`.

### Problema (Iron Law)
- **Síntoma Reportado:** Coordinación de terminal reporta que tras realizar pagos y despachos, en los tableros web de Odoo sí aparecen los turnos despachados y en espera, pero en la app de la Tablet y el Teléfono la lista de despachos dice *"No hay despachos en Garita"* y la cola de vehículos enturnados aparece en 0.
- **Diagnóstico de Causa Raíz (Sin parches superficiales):**
  Al inspeccionar el método de serialización en Odoo `TurnoMovil._get_data()`:
  ```python
  'bahia_sesion_id': self.bahia_id.id,  # 8843 (fundetaxcol.sesion.bahia)
  'bahia_id': {
      'id': self.bahia_id.bahia_id.id,   # 4 (fundetaxcol.bahia física)
      'name': self.bahia_id.bahia_id.name # 'Garita'
  }
  ```
  En Flutter, `TurnoModel.fromJson` al recibir `json['bahia_id']` como `Map` extraía `rawBahia['id'] = 4` y lo asignaba a `bahiaSesionId`, omitiendo por completo el campo `json['bahia_sesion_id'] = 8843`.
  Consecuentemente, en `TurnoController`:
  ```dart
  turnos.where((t) => t.enFila && t.bahiaSesionId == bahiaIdActual.value)
  turnos.where((t) => (t.esDespacho || t.estado == EstadoTurno.despachado) && t.bahiaSesionId == bahiaIdActual.value)
  ```
  Comparaba `t.bahiaSesionId (4) == bahiaIdActual.value (8843)`. Al ser `4 == 8843` falso, Flutter descartaba el 100% de los turnos y despachos de la sesión activa.

### Trazado de Datos
```
[PostgreSQL fundetaxcol]
       │
       ▼
[Odoo 11 /fundetaxcol/turno/get_all]
       │  'bahia_sesion_id': 8843
       │  'bahia_id': {'id': 4, 'name': 'Garita'}
       ▼
[Flutter TurnoModel.fromJson (PUNTO DE QUIEBRE ANTERIOR)]
       │  bahiaIdParsed = rawBahia['id']  --> bahiaSesionId = 4
       │  (json['bahia_sesion_id'] ignorado porque bahiaIdParsed != 0)
       ▼
[TurnoController Filtro Reactivo]
       │  bahiaIdActual.value = 8843
       │  Evaluación: 4 == 8843  --> FALSE (LISTA VACÍA)
```

### Decisiones de Diseño (SDD)

| Alternativa Evaluada | Pros | Contras | Decisión |
| :--- | :--- | :--- | :--- |
| **Opción A:** Cambiar el backend de Odoo para que `bahia_id` sea solo el entero `8843`. | Ninguno en frontend. | Rompe la compatibilidad con otras apps y con tableros web existentes que esperan el dict con el nombre. | ❌ Descartada |
| **Opción B:** Forzar que Flutter solo busque por `bahia_sesion_id`. | Resuelve el endpoint `_get_data()`. | Falla si alguna llamada utiliza `search_read` directo donde `bahia_id` es Many2one `[8843, 'Garita']`. | ❌ Descartada |
| **Opción C:** Soporte de Correspondencia Dual en `TurnoModel` y `TurnoController`. | Captura explícitamente `bahiaSesionId` (8843) y `bahiaBaseId` (4); el filtro compara `t.bahiaSesionId == id \|\| t.bahiaBaseId == id`. Totalmente inmune a variantes RPC. | Ninguno. Mantiene retrocompatibilidad y robustez total. | ✅ **Elegida e Implementada** |

## EJECUCIÓN

### Archivo 1: `lib/models/turno_model.dart`
**Diagnóstico:** El modelo no diferenciaba entre el ID de la sesión diaria y el ID de la bahía base, perdiendo el ID de sesión `8843` al parsear el dict.
**Cambio:**
```dart
// ANTES:
int bahiaIdParsed = 0;
final rawBahia = json['bahia_id'];
if (rawBahia is Map) {
  bahiaParsed = rawBahia['name']?.toString() ?? '';
  bahiaIdParsed = parseInt(rawBahia['id']);
}
...
if (bahiaIdParsed == 0 && json['bahia_sesion_id'] != null) {
  bahiaIdParsed = parseInt(json['bahia_sesion_id']);
}
return TurnoModel(..., bahiaSesionId: bahiaIdParsed);

// DESPUÉS:
int sesionBahiaId = 0;
int baseBahiaId = 0;
if (json['bahia_sesion_id'] != null) {
  sesionBahiaId = parseInt(json['bahia_sesion_id']);
}
final rawBahia = json['bahia_id'];
if (rawBahia is Map) {
  bahiaParsed = rawBahia['name']?.toString() ?? '';
  baseBahiaId = parseInt(rawBahia['id']);
} else if (rawBahia is List && rawBahia.isNotEmpty) {
  final parsedId = parseInt(rawBahia[0]);
  if (sesionBahiaId == 0) sesionBahiaId = parsedId;
  else if (baseBahiaId == 0) baseBahiaId = parsedId;
}
if (sesionBahiaId == 0 && baseBahiaId != 0) sesionBahiaId = baseBahiaId;
if (baseBahiaId == 0 && sesionBahiaId != 0) baseBahiaId = sesionBahiaId;
return TurnoModel(..., bahiaSesionId: sesionBahiaId, bahiaBaseId: baseBahiaId);
```
**Por qué:** Garantiza que el modelo contenga fielmente ambos identificadores relacionales sin importar el formato devuelto por Odoo.

### Archivo 2: `lib/controllers/turno_controller.dart`
**Diagnóstico:** Los getters y métodos de filtrado reactivo (`turnosEnCola`, `turnosDespachados`, `turnosEnColaFiltrados`, `turnosDespachadosFiltrados`, `totalServiciosClientes`, `turnoEnAtencion`, `enturnarVehiculo`) solo contrastaban contra `t.bahiaSesionId == bahiaIdActual.value`.
**Cambio:** Se aplicó la condición de correspondencia dual:
```dart
(t.bahiaSesionId == bahiaIdActual.value || t.bahiaBaseId == bahiaIdActual.value)
```
**Por qué:** Si el controlador tiene el ID de sesión (`8843`) o el ID de bahía base (`4`), la coincidencia es exacta e inequívoca en todos los filtros.

### Archivo 3: `pubspec.yaml`
**Diagnóstico:** Cumplimiento de la regla de trazabilidad física FIX-002 de `ERRORES.md`.
**Cambio:** Incremento de versión de `2.1.13+15` a `2.1.14+16`.

### Archivo 4: `ERRORES.md`
**Diagnóstico:** Registro institucional del problema y la solución para evitar reincidencias futuras.
**Cambio:** Documentado formalmente como **FIX-010**.
